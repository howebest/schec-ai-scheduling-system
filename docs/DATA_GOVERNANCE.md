# 数据口径与治理说明

## 1. 数据来源分层

| 类型 | 位置/形成方式 | 用途与限制 |
| --- | --- | --- |
| 原始样本 | `data/raw_dataset.xlsx` 与参考 CSV | 只读保留；包含岗位、技能与训练主数据 |
| 已验收基准 | `data/baseline_schedule_FULL62_W1.csv` | 只读方案基准；登记 KPI 不等于本机重算 |
| 用户导入 | `data/imported/<dataset_id>/` | 通过字段预览后提交，保存原因、版本和哈希 |
| 合成演示 | `data/demo/` | 固定随机种子生成；用于订单、产能、现场看板和敏感性分析 |
| 本机模拟反馈 | SQLite `feedback` 表 | 仅用于页面和反馈流程演示，不代表真实员工提交 |

## 2. 文件完整性

原始输入哈希保存在 `data/INPUT_SHA256.txt`。演示生成器写入 `data/demo/manifest.json`，记录种子、来源、行数、列和 SHA-256。导入文件在预览和提交间会重新计算 SHA-256；内容发生变化时拒绝提交。方案 CSV 在下载时按方案登记哈希校验。

Python vendor 依赖在目标 macOS arm64 / CPython 3.11 构建后写入 `vendor/python/macos-arm64-cp311/SHA256SUMS`。

## 3. 排班约束与 KPI

- 12 h 班次当前按 11 h 计薪工时，其中标准 8 h、加班 3 h、1 h 用餐不计工时。
- 8 h 常白班按 8 h 计薪。
- 已验收硬约束包含每日工时、月加班、滚动休息、相邻班次间隔、技能/夜班资格和岗位覆盖账目。
- 历史基准登记覆盖率：求解需求口径 85.28%；岗位台账与运行计划重建口径 85.03%。两者口径不同，应同时说明。
- 历史基准登记整班指派 9,693 人班、缺口 1,753 人班；关键岗缺口 990 人班、一般岗缺口 763 人班。它们是登记值，不是本机求解运行结果。
- 数据报告说明的关键岗口径差异包括岗位台账与 `input_04` 是否关键岗位字段的分歧。页面不把历史双口径差异折叠为单一现场事实。

## 4. 合成数据限制

订单、线速、效率和 14 d 可用产能由固定种子生成，不参与当前 MIP 目标或约束。合成考勤记录仅显示快照状态。由其计算的订单需求、产能利用率和到岗统计属于演示值，不可用来证明实际产量、出勤率、交期达成或节省金额。

## 5. 个人信息与本机存储

员工编号、技能、证书有效期和排班可能属于个人信息。运行目录仅限受控本机用户访问。系统尚未提供账号认证、字段级加密、远程审计、数据自动到期删除或多用户隔离；组织正式使用前需补充安全设计和审批。
