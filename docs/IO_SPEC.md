## 2 输出文件

### 2.1 solve-demo / solve-full（--out）
排班方案CSV，与基准方案同构的三段式格式（指派、缺口记录、非完整班次记录）。
stdout 输出JSON：终止状态、目标值与下界、目标复算值、建模与求解耗时、
模型规模、七项硬约束独立核验结果、KPI分量、输出文件SHA-256。

### 2.2 verify-baseline
stdout 输出JSON：七项硬约束违例计数、KPI复算、目标复算、与已验收基准
登记值（FULL62-W1）逐项比对结果、ISS-01双需求口径参考值。退出码0=通过且
与登记值一致，4=核验存在违例，5=与登记值不一致。

### 2.3 reschedule（--out-dir）
目录内输出：
- `rescheduled_schedule.csv`：合并全期方案（窗口外基准+窗口重排），三段式格式；
- `scenario_result.json`：事件与窗口、解锁与锁定规模、响应时间分项（场景配置/
  建模/锁定与边界/求解/解提取）与合计、60秒达标、求解状态与上下界、变更与
  受影响人数、重排前后KPI、全期七项硬约束核验结果；
- `reschedule_changes_detail.csv`：逐条取消/新增指派与缺口变化明细；
- `fractional_shift_detail.csv`：场景级非完整班次明细（员工、岗位、日期、小时、
  是否事件窗口内），落实独立核验建议；
- `backfill_recommendations.csv`（离岗场景）：每空缺前5名补位候选，技能等级、
  岗位要求等级、证书有效期、可胜任夜班、画像累计在岗时长逐字段取自人员技能矩阵；
- `dispatch_archive.csv`：调度记录全量归档（append-only）；
- `external_messages/`：企业微信/短信/考勤/MES/OCC/手环模拟适配报文与回执
  （明确标注SIMULATED，未连接真实系统）；
- `kpi_report.md`：方案KPI简报。

### 2.4 kpi（--baseline --out-dir）
`kpi_place_rows.csv`（处数KPI统一输出）与 `kpi_report.md`。

## 3 口径与限制
1. 12小时班计薪11小时=标准工时8小时+当日加班3小时（另1小时用餐不计工时），
   该口径经前置解析4683行样本恒等式核验；月加班上限36小时等价于每人每月
   12小时班不超过12班。
2. 两班间隔不少于11小时与7天至少休1天按整班排班序列时间戳判定；非完整班
   小时与整班之间的间隔和休息判定未建模（沿用已验收模型口径，交付文档如实标注）。
3. 结构性人力容量缺口：392人×12班/月×2月名义容量9408人班对62天需求11912
   人班，当前人力下100%覆盖不可行；缺口为结构性结果，方案按权重最小化缺口，
   不构成100%覆盖承诺（独立核验ISS-01双口径下覆盖率85.28%对85.03%）。
4. 产能与交期约束因订单类字段未填充按外部参数处理，未虚构数值。
5. 输入为规则驱动仿真样本，输出结论不构成实际工厂绩效证据。
6. 外部系统对接为设计与模拟适配，未与真实系统联调。
