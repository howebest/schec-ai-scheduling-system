# 演示培训与验收步骤

## 1. 培训前检查

1. 在 macOS arm64 设备完成 `./run.sh build`。
2. 运行 `./run.sh start` 并打开 `http://127.0.0.1:8080`。
3. 检查首页健康状态、默认已验收基准数据和数据来源标签。
4. 在模型页面查看可调用的 Pyomo/HiGHS 排班 MIP、机器学习训练模型数量、版本链、目标权重和约束说明。确认训练模型数量为 0；不要把 MIP 模型或规则评分称为已训练机器学习模型。检查 FULL62-W1 仿真基准的双口径覆盖率说明及按产量生产力不可计算的原因，并预览或下载两份阶段报告。报告统计和性能数值是阶段报告记录，不作为真实工厂实绩或本机完整周期验收结论。KPI 报告文件名版本为 SCHEC-KPI-V1.0.1、正文标题版本为 SCHEC-KPI-V1.0，演示时按两项原始标记说明。

## 2. 建议演示顺序

1. 运行总览：解释历史登记指标与本机计算指标的差异。
2. 数据管理：选择 `orders` 模板下载表头，执行 CSV 预览；再上传随意缺失字段文件展示逐字段错误；通过预览后登记独立数据集版本。
3. 排班任务：使用已验收基准数据运行数据概况或基准复核，观察异步状态、终止状态和任务原因记录。
4. 方案管理：查看基准方案、CSV 摘要和哈希；提交独立核验。未通过或未核验时不得锁定或模拟发布。
5. 异常调度：选择一个事件，核对事件日期与实体是否属于当前输入数据；提交后查看新任务和新方案版本。
6. KPI 与解释：比较整周期与日期范围指标；切换合成数据查看订单/产能参数敏感性，并说明分析结果不进入 MIP 求解。
7. 排班数据分析：选择已登记方案，按日期、工厂、产线、班次和岗位筛选；查看覆盖与缺口趋势、产线日期热力图、员工工时分布、四分位距异常提示及维度统计。说明数据来源、单位和筛选限制，特别是缺口记录缺少工厂代码时仅按唯一产线映射归属。
8. 排班管理分析：检查单方案覆盖率、工时分布、独立核验、缺口明细和日趋势；选择 2 至 5 个同数据版本方案，对比覆盖、投入工时、加班、公平性、约束核验和满意度。说明计薪工时不是货币成本，雷达分数仅对所选方案归一化。
9. 现场模拟看板：查看固定随机种子考勤快照，确认页面标记和免责声明。
10. 规则和审计：保存规则版本并填写原因；指出规则版本记录不会自动改变源模型常量。
11. 调度档案：按数据集或日期筛选并下载 CSV，说明哈希校验。
12. 员工反馈与连接器：新增关联具体方案的本机模拟反馈，可选填写 1 至 5 分；确认无评分时分析页显示“无可计算值”，外部系统仍为“未连接”。

## 3. 关键验收判断

- Python 依赖缺失、无可行解或超时必须明确显示失败原因，不能显示“已完成”。
- 只有独立硬约束核验通过的当前方案版本才允许锁定或模拟发布。
- 旧版本 `expected_version` 请求应返回冲突，并提示刷新。
- CSV/事件导入需检查列名、格式和日期；字段错误时不能登记数据版本。
- 合成演示值不得标记为真实 HR、MES、考勤、产量或订单事实。
- 静态页面和 API 必须通过 Rust 单端口提供；刷新页面路由不会返回 API JSON 错误页。

## 4. 明确限制

本演示不构成真实生产现场验收，不证明真实 HR、APS、MES、考勤或通知系统已完成联调。现有 package 源码没有训练好的机器学习模型。基准登记 KPI 与本机重新求解、复核结果应分别展示。
