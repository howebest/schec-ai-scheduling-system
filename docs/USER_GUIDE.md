# 本机工作台使用说明

## 1. 系统用途

本系统用于本机运行排班 MIP 求解、异常场景增量重排、独立约束核验、数据导入预览、方案复核与指标分析。页面中的“合成演示”和“本机模拟反馈”记录不对应现场实绩。HR、APS、MES、考勤、消息及定位系统未连接。

## 2. 启动与入口

完成 Mac arm64 发行构建后，在工程包根目录执行：

```sh
./run.sh start
```

默认页面地址为 `http://127.0.0.1:8080`。服务状态、停止与日志查看命令见[运维说明](OPERATIONS.md)。源代码包在构建二进制、前端静态资源和 Python vendor 目录前不能启动完整服务。

## 3. 页面说明

### 运行总览

显示当前数据版本、最近任务、岗位覆盖率、未覆盖需求和加班工时。已验收基准登记值与本机求解结果通过来源标签区分。覆盖率不代表现场出勤或产量。

### 排班任务

支持数据概况检查、7 天演示求解、62 天整周期求解、基准方案复核和 KPI 复算。每次任务需选择数据集、任务类型、时限、操作人、角色和提交原因。求解输入须为原始 XLSX 工作簿；合成订单和产能数据仅供统计分析。

任务记录显示排队/运行/结束状态、求解器终止状态和时间。任务状态与 HiGHS 终止状态分开解释。达到时限或没有可行解时，不能将任务标为成功方案。

### 方案管理

展示方案版本、文件哈希、排班指派、岗位缺口和非完整班次。方案可独立核验、人工调整、复核、锁定、驳回或模拟发布。每次修改使用当前版本号；旧版本会冲突拒绝。锁定或模拟发布要求当前版本的硬约束核验结果为通过。

人工调整字段包括操作类型、员工编号、岗位编码、日期和班次编码。调整提交后会生成新方案版本，并重新运行独立核验。

### 异常调度

支持插单、增产、换产、设备故障停线和员工突发离岗五种事件。事件日期和实体编号必须存在于当前原始工作簿。页面默认编码来自随包场景样例；提交前须按实际选择的数据集检查并调整。

### 现场模拟看板

读取包内 2026-10-01 至 2026-10-14 合成考勤快照，可按日期和班次过滤。统计结果统一标记为“合成演示”，不能作为正式考勤报表。

### 人员与技能

人员与技能页包含员工档案、班组管理、岗位人员与产线资格、员工本人排班查询四个页签。员工档案维护编号、姓名、主要岗位、所属班组、技能名称及评分、协作评分和归档状态。技能评分为有效技能中已评分项目的算术平均值；综合评分只有在技能均分和协作评分都存在时才计算。缺少评分时显示“无可计算值”，不按 0 分处理。

班组目录显示有效成员数和具备资格的适用产线数。岗位人员与产线资格页维护员工或班组、产线、岗位之间的本机关系。该关系仅供本机轮转配置校验，不等同于证书或 HR/MES 系统验证。新增、编辑、归档或停用时均须填写操作原因，记录保存在本机并显示来源标签。

“员工本人排班查询”通过员工姓名搜索并选择员工档案，选项同时显示员工编号以便确认。查询时使用所选档案的员工编号检索所有已登记方案档案，并在结果中显示数据集名称；查询不受顶部数据集选择和列表预览行数限制。本机演示不接入员工身份认证，查询结果不用于正式员工通知。

### 排班配置

排班配置页用于维护本机轮班周期，包括配置名称、产线、按班组或员工轮转、有效日期、班次定义、周期日明细和轮转对象偏移。班次时间使用 24 小时制 `HH:mm`；结束时间早于开始时间表示次日结束。周期长度必须与周期明细行数一致，每个周期日只能选择一个班次或设为休息日。偏移量范围为 0 至周期长度减 1。

配置保存前会调用服务端校验名称、产线、日期区间、周期序号、班次编码、对象状态、产线资格及日期冲突。配置可以查看、编辑、复制、启用和停用；复制生成停用副本。启用前必须再次满足完整校验。写入操作需要填写原因，形成本机审计记录。初始化汽水线与无菌线轮转配置、班组和员工使用“合成演示”来源；新增和复制的维护记录使用“本机配置”来源。

### 排班日历

排班日历页提供月视图和周视图，可按产线、启用配置及日期筛选。日历由 Rust 服务根据生效日期、周期长度、周期日和对象偏移即时计算，查询范围最多 62 个自然日。计算公式为：`(查询日与生效日的自然日差 + 对象偏移量) mod 周期长度`，再加 1 读取周期日。跨午夜班次归属开始日期，并在结束时间旁标注次日结束；休息日显示“休息”；没有适用配置的日期显示“未配置”。

本机轮转配置和日历是独立管理能力，不是 MIP 求解方案或生产排班结果。新增配置不会改变既有求解器输入、规则约束或方案文件；HR、APS、MES 等外部系统未连接。

### KPI 与解释

显示整班指派、覆盖率、岗位缺口、关键岗缺口、加班、计薪工时及员工工时分位数、基尼系数。每项指标说明单位、样本数、来源和定义。指定日期范围时，仅计算文件中可按日期拆分的字段；文件没有的类别字段显示“无可计算值”。

合成订单与产能敏感性视图只按需求和可用产能比例变化计算估算利用率，不重新执行人员排班优化。

### 排班数据分析

本页从页面顶部选定的数据版本中读取一个已登记排班方案的完整 CSV。方案选择器默认选择最近登记的方案；日期范围、工厂、产线、班次和岗位筛选器用于限定本次统计的样本。更换方案会重新读取明细并清除原筛选条件。页面只在本机浏览器内存中计算，不创建或修改排班方案。

摘要卡展示需求人班、人力覆盖率、未覆盖需求、加班工时、有排班员工数和纳入日期数。需求人班由整班指派数、非完整班次工时按 8 h 折算的人班数及岗位缺口人班组成；覆盖率按已覆盖人班除以需求人班计算。结果可按日查看覆盖率和缺口趋势，按产线与日期查看覆盖率热力图，并按产线、班次和岗位展开统计。员工工时分布同时列出 P25、中位数、P75、四分位距、工时极差和基尼系数。

统计诊断会标出缺口最高的产线、员工日加班超过 3 h 和员工月加班超过 36 h 的明细计数、四分位距异常样本数，并在日期样本不少于 3 天且数据有变异时计算需求与缺口的 Pearson 相关系数。加班计数按当前日期和维度筛选后的指派记录计算；选择部分日期时，月累计值也只覆盖筛选范围内已登记的记录。相关系数仅描述当前样本的线性关联，不说明因果关系；四分位距规则用于提示复核对象，不单独认定排班错误。

缺口记录没有工厂代码。系统仅在产线可唯一映射到工厂时，将该缺口归入工厂筛选；产线或岗位存在多重映射时不作推断。非完整班次记录通过岗位和班次代码与已登记明细映射；无法唯一映射时，相关维度可能显示“未记录”或不参与该维度筛选。页面结果为已登记方案文件的统计，不代表实际到岗、工资、考勤或产量。

### 排班管理分析

单次分析读取所选方案的完整 CSV，展示覆盖率、未覆盖人班、计薪工时、加班工时、员工工时基尼系数和工时极差。覆盖人班按整班指派数加非完整班次工时除以 8 h 计算；需求人班为覆盖人班与缺口人班之和；覆盖率为覆盖人班除以需求人班。日趋势展示覆盖率和加班工时，热力图按产线与日期展示缺口人班。

系统识别岗位缺口、独立核验未通过、员工日加班超过 3 h、员工月加班超过 36 h。核验项沿用方案版本已登记的独立核验结果；没有核验记录时显示“未核验”。多方案对比仅展示当前数据版本中的 2 至 5 个方案，可切换比较覆盖率、计薪工时、加班工时、工时基尼系数和满意度。雷达图只包含所有选中方案均有值的指标，并按当前所选方案范围归一化到 0–100 分。

计薪工时是人员投入量的成本代理，不是货币成本。满意度只计算关联到所选方案版本的有效 1 至 5 分反馈；员工反馈页面新增了可选评分项，未填写评分或没有关联反馈时不计算平均值。该评分样本保存在本机，不能解释为真实员工调查或总体满意度。

### 排班决策实验室

本页由方案比较、情景推演和缺口与约束解释组成。方案数据读取当前顶部数据版本中最近登记的最多 100 条方案档案及其完整 CSV；每条方案保留方案编号、版本、任务、数据来源和核验状态。CSV 或反馈读取失败时显示对应方案编号和错误，不用空值补造指标。

方案按数据集版本、CSV 排班日期范围、需求人班总量、产线—岗位—日期—班次需求结构和方案登记的 `comparison_group` 分组。仅需求总量相同但需求结构不同的方案不会进入同一 Pareto 前沿；日期范围、需求总量或结构无法确认时，该方案单独成组。组外方案列表会说明不纳入原因。

Pareto 散点图横轴为工时成本代理值，纵轴为需求覆盖率，圆点大小参考员工工时基尼系数。蓝色点代表在“覆盖率越高越好、成本代理值越低越好”两项指标上没有被同组其他方案同时支配；它不代表唯一最优方案。缺少覆盖率或工时成本代理值的方案不参与前沿计算。表格同时显示需求人班、覆盖率、成本代理值、工时公平性、加班工时、核验状态和满意度样本数。满意度只取关联到方案版本的有效本机反馈，无样本时显示“无可计算值”。

情景推演只对来源为“已验收基准”或“用户导入”的数据集开放。基线方案、员工、产线、日期和班次选项均从当前数据版本及所选基线 CSV 读取；切换基线时，依赖基线的已选员工、产线、日期和班次会清空。事件字段如下：员工突发离岗需要员工编号和离岗日期；设备故障需要产线和起止日期，提交时展开为区间内该产线在基线 CSV 中记录的全部排班日期；增产需要产线、日期及每岗位人数增量；插单和换型需要产线、日期及班次。日期仅允许选择基线 CSV 已记录日期，事件最终有效性由 Rust 服务调用既有适配器预检。

提交前需要选择基线方案，填写情景名称、操作人、服务端允许的操作角色和提交原因。Rust 服务创建并管理现有重排任务，页面每 5 s 刷新任务状态；状态读取中断时显示最近一次成功读取时间并继续自动重试。求解成功且结果通过已有独立核验并登记为新方案后，页面展示结果版本、新增及取消的整班和非完整班次指派、岗位缺口变化和 KPI 差值。差值按“结果方案－基线方案”计算；指标缺失时显示“无可计算值”。任务失败、取消、无可行产物、核验未通过或结果未登记时，基线方案保持不变，页面不会将其标为成功新方案。

缺口解释按方案 CSV 的产线、日期、班次、岗位、指派和缺口记录列出需求人班、已覆盖人班及未覆盖人班，并提供分页明细。独立核验通过、未通过和未核验分别呈现；可识别的违规计数与样例注明 `verification` 字段来源。规则模拟计数明确标注为非独立核验；缺少可计算计数时不显示为 0。只有核验记录实际返回员工和岗位资格违规样例时才展示相应资格线索。缺少技能矩阵、证书或核验样例时显示“现有数据无法判定原因”，不根据未排班状态推断技能不匹配。标记为场景规则模拟的方案不会被显示为独立核验通过。

工时成本来自现有排班管理分析口径，是本机演示费率计算的代理值，不是企业实际工资或财务成本。合成方案及本机模拟反馈只用于页面功能和分析流程演示；HR、APS、MES、考勤及其他外部系统未连接。

### 调度档案

按数据集、来源、员工、工厂、产线、日期和班次筛选登记方案。CSV 下载会按登记 SHA-256 校验文件内容。

### 规则配置

保存规则快照时必须填写变更原因。当前页面值用于规则版本管理和审计；已有 MIP 约束常量仍以已验收模型源代码为准，修改规则快照不会自动修改求解约束。

### 模型与算法

本页区分可调用的运筹优化模型与机器学习训练模型。当前可调用的排班模型为 SCHEC-MIP-V1.0，采用 Pyomo ConcreteModel/ConstraintList，通过 Pyomo Appsi 调用 HiGHS 1.15.1；Rust 任务服务统一管理 CPython 3.11 子进程，任务契约见 `src/service_adapter.py`。机器学习训练模型目录为 0 项；候选补位排序属于规则评分，不产生模型概率或置信度。

版本链覆盖输入、MIP 建模、基准求解与权重实验、异常增量重排、独立核验、KPI 可视化和本机工程包。页面列出目标权重、约束族、阶段报告基准与本机 7 d 演示验收结果。FULL62-W1 报告指标使用规则驱动仿真样本，不代表真实工厂绩效；求解口径与独立核验重建口径的需求量相差 36 人班、6 个班次。计划产量字段未填充，因此不能计算按产量的制造生产力。

在“阶段报告与验收证据”区域可在线预览或下载两份随包 HTML 原件。KPI 报告文件名版本为 SCHEC-KPI-V1.0.1，正文标题版本为 SCHEC-KPI-V1.0；系统分别展示两个原始标记，不作版本推断。报告内的完整周期规模、求解性能和阶段实验数据属于报告记录值；本机复现范围以页面状态和验收记录为准。

### 数据管理

选取 CSV、XLSX 或 JSON 文件后，先进行字段预览。通过检查后填写数据集名称和登记原因，再复制到工程包数据目录并创建带 SHA-256 的版本。原始工作簿与已验收基准保持只读。

`原始求解工作簿（XLSX）`需要包含设备产线与工位台账、人员技能矩阵和排班训练主数据集。订单、产能、考勤、岗位需求、运行计划、基准方案和事件模板不自动转换为求解工作簿。

### 连接器状态与员工反馈

连接器页面列示 HR、APS、MES、考勤、订单、质量、仓储和消息接口的业务范围，状态均为未连接。反馈页写入本机模拟数据并记录来源；没有向外部服务发送通知。反馈可选填写 1 至 5 分满意度并关联方案编号，只有关联到具体方案版本的评分会进入排班管理分析。

## 4. 来源标签

| 标签 | 含义 |
| --- | --- |
| 原始样本 | 项目随附输入样本 |
| 已验收基准 | 项目交付的基准数据或方案登记值 |
| 用户导入 | 用户通过预览与提交流程登记的文件 |
| 合成演示 | 固定随机种子生成的本机演示数据 |

| 本机模拟反馈 | 存储在本机的模拟员工反馈 |

## 5. 角色和审核

任务、规则、人工修改、审批和数据提交均保存操作人、角色和原因。演示环境没有接入统一身份认证；页面内填写的角色不构成企业账号认证或权限集成。
